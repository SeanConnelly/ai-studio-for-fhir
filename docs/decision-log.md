Project decisions for FHIR Agent Studio, most foundational first; dated entries are work-log style records of major build rounds. Referenced from `CLAUDE.md`.

- **Router:** hash (`#/...`). Simpler than history mode and judges won't deep-link.
- **IRIS image:** `intersystemsdc/irishealth-community:latest` (FHIR features + Vector Search built in).
- **GitHub repo:** Sean is provisioning. Phase 8 will tag and push.
- **LLM provider:** xAI **Grok** (`https://api.x.ai/v1`, OpenAI-compatible), model `grok-4.20-0309-non-reasoning`. Verified live from ObjectScript.
- **Embedding model:** Grok has **no** embeddings endpoint, so embeddings come from **local Ollama `all-minilm`** (384-dim, OpenAI/Ollama-compatible over HTTP at `host.docker.internal:11434`). Real vectors are generated once at dev time and **bundled** (`seed/llm-cache/embeddings.json`); `Embedder` uses the same record/replay cache as the LLM (cache hit → bundled real vector → live Ollama on miss → deterministic hash only as a last resort), so the key-free demo replays genuine model embeddings with **no provider needed**. The local hash is the safety net, never the demo path. (Done 2026-05-26; verified offline via the unreachable-provider test — EmbedAll replays `source=cached`.)
- **Vector Search:** native IRIS Vector Search, not a keyword stub.
- **Runtime = REAL IRIS Interoperability Production** (decided 2026-05-25 after the "are we faking it?" review): `Ens.Production` + real BS/BP/BO + messages, replacing the synchronous plain-class runtime and the `HC.Agent.*` labels.
- **Package rename:** `FHIRAgentStudio` → `FAST`, schema → `FAST_Data`, web path unchanged (`/fhir-agent-studio/`). Complete — classes, SQL schema, and the source folder (`iris/src/cls/FAST/`) are all `FAST`.
- **Truthful agent re-architecture (2026-05-27):** the agent step was inverted — code built a deterministic result and the LLM only *overlaid* prose; the NL→FHIR "generated query" was a hardcoded string. Fixed so the **LLM authors the entire result** for the 3 heroes (summary/findings/recommendations, the draft FHIR action, prior-auth met/missing/justification, and the NL→FHIR query). Flow: real RAG (FHIR/SQL/vector) → combined with the base prompt into one completion request → LLM → its JSON **is** the result. NL→FHIR: the LLM writes real SQL against the `HSFHIR_X0001_S` FHIR SQL projections, which we **validate read-only** (`AIHubOperation.IsReadOnly`) and **execute for real** via `%SQL.Statement` (control-char strip on text cells, since the projection string columns carry collation-prefix bytes). The deterministic `Build()` scaffold survives only as the no-key/no-cache fallback (source `deterministic`, never shown as AI). `PROMPTVERSION`→2, cache rebuilt (all 12 via `CacheBuilder.BuildAll` → `seed/llm-cache/completions.json`). Every run records base prompt + combined request + raw response into `resp.aiTrace`, shown as a **completion transcript** in "Under the hood". Prompts forbid leaking internal vocabulary into clinician text. Smoke 11/11.
